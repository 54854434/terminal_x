# Terminal X v0.3.2

## R33 分时连续线和真实动态盘口

- 分时图当前游戏分钟采用连续、从左向右延伸的逐帧指示价轨迹，秒级轨迹保留已采样拐点，每分钟确认收盘后接续新分钟。不会只显示边缘一个左右晃动的点，也不会把指示价写成真实成交、成交量或 SQLite 已提交 OHLC。
- 5分／15分／1时等周期绘制单一合成预览蜡烛：同一周期已有已提交蜡烛时，不再额外画一根重叠的 1 分钟蜡烛。历史实心 K 和交易记录仍按已验证 SQLite 数据呈现。
- 有模拟参与者的新会话：LP_A/LP_B 的真实买卖委托价格、数量根据每分钟市场状态有界变化，变更经真实资金／库存约束、普通挂撤单和价格时间优先撮合引擎提交；不构造幽灵挂单或伪造交易量。旧会话／没有 NPC 账户的旧语义保持不变。
- 真实五档新增上一修订挂单增减标记，清楚区分“已提交委托”和帧级指示走势。经济性 NPC 挂撤单仍按完整游戏分钟执行；未提交的秒级指示不会误充为可撮合的订单。
- 倍速改成一排常用快捷选项、±1／±10 调节及自定义数字输入；继续同时显示目标倍率与真实已提交倍率，不跳过游戏分钟。
- 继承 R32 自动分钟提交时不停止 Vsync、取消人为 60 分钟强停、5分及以上指示高低点按周期保留的改动。

## 存档原则与后续改造

- 本次保留每游戏分钟 SQLite 原子提交及可自定义 1～64 次提交的完整检查点频率。**每 N 游戏分钟才提交一次／手动保存模式尚未实现**；实现该模式需要单独设计未落盘会话的断电丢失窗口、玩家交易立即落盘和恢复语义，不能让 UI 设置与真实存储行为不符。
- app ID、签名路线及旧 SQLite schema 1 保持不变。新候选版本 0.3.1+31 可覆盖 0.3.0+30，但需通过 GitHub CI Flutter 回归和签名 APK 构建后再发布。


## R34：长历史性能与资产实时预估
- 市场逐笔默认展示最新 24 条，按需每次追加 24 条（最多展示 120 条），使用列表虚拟化，原始成交及账本不删除。
- Android 启动先绘制恢复界面；冷启动快照增量回放、JSON 导入和账本审计转移到独立 Isolate，保持严格校验。
- 资产页面按与分时图相同的临时指示价逐帧估算总资产和浮动盈亏；现金、冻结和真实成交仍以 SQLite 成功提交为准。
- 保留 0.3.1+31 的 R33 分时连续曲线、K 线预览去重及盘口真实变动。
- 不进行有风险的历史数据剪裁，也不改变已有 SQLite schema/签名/应用 ID。


## R35: Rust 混合内核起步／长期架构准备
- 增加独立、无第三方依赖的 Rust 价格时间优先撮合原型：资金／股份冻结、撤单、真实成交、数量与资金守恒校验，使用纯整数。
- 新增 C ABI v1 与 Dart 显式加载桥接类；Rust 核心和 Flutter UI 通过稳定函数接口隔离，为后续扩展标的、NPC 与更多游戏业务留出结构边界。
- 保留原 Dart 交易引擎作为生产唯一可信执行路径，所有旧 SQLite schema 1 账户、订单、持仓、账本保持不变。
- Rust 源码暂置于 scripts/tx_native_core：现有一 ZIP APK 工作流尚不能打包 Rust ARM64 .so，也不会执行 cargo test。本批不启用原生执行、不宣称性能提升。
- 正式启用前需扩展 CI 和 Android 原生构建，完成同订单流 Dart/Rust 逐笔一致性、原有存档导入／回放、错误回滚、实机 p95 测试。


## R36: Rust ABI v2 与确定性交易命令日志
- 保留全部 R34 可见体验修复及 R35 Rust 源码；默认 Flutter APK 继续使用已经验证的 Dart 撮合执行后端。
- Rust ABI v2：新增固定 80 字节交易事件记录、命令日志读取、回放重建、当前委托状态与活动订单数查询。
- Rust 原生回放单元测试覆盖部分成交、取消、追加标的、IOC 剩余量、幂等重复调用和篡改执行结果拒绝。
- 新增 scripts/tx_native_core/dart_rust_parity.dart，待原生 .so 编译后用同一 funded 订单流检查 Dart/Rust 的现金、冻结资金、持仓、委托和成交是否一致。
- **本批尚未启用 Rust 游戏后端**：现有 ZIP 导入工作流不编译/打包 Rust Android so，Rust 编译、设备测试与真正的 CI 仍需单独完成；不宣称已获得原生加速。
- 你目前的测试玩家存档允许重置，后续可以重新设计 Native 引擎的持久化协议，但本候选不会主动清除任何现有 SQLite 数据。


## R36 CI Hotfix 1：分时切换与指示价标签
- 修复分时显示哨兵周期（0 分钟）错误传入正整数周期影线累计器而导致 Flutter Widget 构建异常。分时只使用连续分钟内曲线，不绘制蜡烛影线。
- 恢复 1 分钟 K 线的“指示价（非成交）”显式标签；未提交价格仍不能进入真实 OHLC、成交或账本。
- 已有 `tx_frame_preview_test.dart`、`tx_multi_timeframe_widget_test.dart` 和 `tx_market_ui_perf_test.dart` 覆盖这三项 CI 故障；未移除、跳过、放宽任何测试。
- Rust ABI v2、事件日志、旧 GitHub 基线与 v0.3.1+31 版本不变。Rust 原生 Android 编译仍未启用。


## R37 0.3.2 图表绘制修复
- 分时图每分钟只向绘制器提供符合实际像素宽度的连续采样点，保留真实最新秒级报价，修正高倍速右端密集折返。原始指示价记录及历史已提交数据不变。
- 1 分钟图恢复空心青色实时预览蜡烛（最高/最低/开/当前指示价）；预览仍不可成交、不进入 OHLCV 或 SQLite。
- 5 分及更大周期仅保留选中周期的单根聚合预览；空心柱影线只绘制在柱身外面，消除双线套叠错觉。
- 现有真正订单簿仍每分钟更新。秒级真实挂单、撤单与玩家可成交订单状态同步需要交易调度重构，未以虚假盘口数字冒充完成。
- 每分钟暂停是撮合/SQLite 提交背压，与 60 游戏分钟的人为强制暂停不同；该安全等待在本版仍可能可见。

- Android 返回键不再立即退出：交易、资产、记录页面返回行情；行情页面暂停并询问是否退出。数据库提交进行中不可直接退出。
- 启动画面仍可先绘制，历史恢复仍进行完整校验；深层次冷启动耗时属于后续专项基准优化，未声称已消除。

## R38 Rust-first 交易内核直接启用
- **Android 正式游戏市场线程启用 Rust ABI v2**：Rust 先处理每笔真实委托、撤单、NPC 挂单及撮合，Dart 仅生成用于现有 UI/SQLite 的投影。
- 游戏改用独立的 `terminal_x_rust_v1.sqlite`，原有测试存档不导入、不删除。
- Native command journal 进入原子 SQLite 修订，重启时重放并验证资金、冻结股数与真实成交。
- 严格模式：Rust 载入失败、账本结果不一致即禁止继续交易，绝不静默退回 Dart。
- **NPC 当前仍采用原来的每游戏分钟决策周期**；尚未实现秒级真实盘口。
- 当前 CI 原生编译链必须更新，且本包未在本机完成 Flutter 或 Rust 运行测试。


### R38 首次构建修正

- 保持 Rust 原生引擎、ABI、市场撮合、NPC 逻辑、存档路径及 APK 签名机制不变。
