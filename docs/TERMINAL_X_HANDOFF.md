## 一、产品定位和开发权限

完全离线、Android 单人、无真实交易资金的虚拟金融市场交易游戏；以 A 股、美股、期货、外汇、加密货币五大市场为最终目标。玩法包括多资产资金管理、真实订单簿、独立规则、有限资金/库存 NPC、事件新闻、风险预算、滑点、费率/保证金/强平（需真实实现后才上线）。参考 OKX / Gate 的行情分析、K 线、盘口、订单、资产、记录页布局及交互密度，保留 Terminal X 深蓝黑、青绿 X 图标和独立品牌，不复制交易所素材。

**用户明确授予广泛研发自由：允许替换整个撮合引擎、SQLite schema、状态管理、Flutter UI，甚至技术栈；每版可同时大范围开发和性能治理，不被旧源码结构、旧路线图或补丁范围束缚。** 性能数据支持的 Kotlin/Jetpack Compose、Rust、C++ 混合方案可以采用，不为换语言而换语言。新的代码必须具备清晰职责和删除旧临时代码的退出条件。

唯一不能牺牲的硬条件：应用 ID `com.terminalx.game.terminal_x`、桌面名 `Terminal X`、同一私密正式签名、versionCode 递增、同应用覆盖升级、原有用户 SQLite/其他私有存档不被清空、所有资金/库存/流水/成交的账务审计、真实有限撮合、不伪造价量、离线运行。错误存档必须停止写入，不准自动建立空账户覆盖。

## 二、当前实机反馈（最高优先级）

V0.2.5 手机截图证实可运行至 60×、第 67 模拟分钟及 SQLite r74。用户持续反馈 **60× 下 K 线逐根闪现／加载，不像真实分钟内持续波动、很多 K 没有显著影线、仍有卡顿、冷启动较慢**。V0.2.6 已导入并生成 Release，但不能据此假定上述反馈已解决。

根因定位：

- `TxSession.nextTick()` 只在完整游戏分钟内集中撤单、挂单和 NPC 撮合；真实经济时钟还不是游戏秒级。即使 UI 高频刷新，也无从显示尚未成交的真实逐笔。**无影线不必然是 bug**：该分钟成交高低恰好是开收点时应没有影线；禁止用虚构成交价或无来源的高低价美化蜡烛。
- `TxEngine.checkInvariants()` 在大量 place/cancel 后全量扫描累计账务和成交；每个 Fill 还全量扫描账本匹配行，复杂度高。
- `TxSqliteStore.saveSession()` 每分钟完整存储累计订单+Fill+Ledger 的 JSON 快照。`readHistory(limit:64)` 冷启动反复解析并审计 64 个大快照。
- V0.2.6 将整分钟计算移入后台 Isolate，但完整 SQLite 审计、序列化和快照仍昂贵；数据库慢时游戏主动降速以保护账务，绝不补跳未提交分钟。

## 三、V0.2.7+27 这一候选包的实际变化

**本批是向事件化市场演进的一步，不是连续秒级撮合的最终完成版。**

1. `lib/storage/tx_trading_service.dart`：玩家买卖及撤单候选会话的复制/ JSON 序列化/实际下单计算，改至 Dart Isolate；和已有后台推进模式一致。成功 SQLite 事务提交后才能更新 `current`，操作期间拒绝并发第二笔。旧版现有数据、订单格式和数据库 schema 不变。
2. `lib/market/tx_market_event_tape.dart`：根据**相邻、已提交的 SQLite 修订**，仅抽取新增真实 `TxFill` 事件，附分钟号和**顺序号（不是虚构的游戏秒时间戳）**；独立按成交价累积开高低收量。没有 Fill 就是零成交记录，报价变化永不当作成交。暴露为可选 `nextTickWithTape()`，为下一阶段事件时钟及图表接线提供严格源数据。**现有 K 线仍来自原有分钟快照，此时尚未接入该新事件源。**
3. `test/tx_market_event_tape_test.dart`、`test/tx_worker_trading_test.dart`：验证真实成交顺序、多档成交、无假成交、跨修订拒绝、资金冻结释放、隔离线程下单和并发拒绝。全部现有 15 个测试文件继续运行，新增后合计 **17 个 `tx_*_test.dart` 文件**。
4. `scripts/tx_release_notes_zh.md`：按版本编号编写中文 Release 说明，明确已改进、仍存问题和安装风险。
5. `pubspec.yaml` 升级到 `0.2.7+27`；不更改图标 PNG、包名、签名、存储 schema，不增加云服务或真实交易。

**构建验证边界：** 本地文件生成环境没有 Flutter SDK，静态语法/ZIP 哈希可核对但未运行 flutter test / 编译。必须等待 GitHub Actions、签名验证和手机覆盖安装。严禁描述 60× 卡顿或真实分钟内行情已修复。

## 四、下一步可大范围重构方案（无需按小补丁版本推进）

### A. 真正游戏秒级事件驱动

- `SimulationEventClock` 与渲染帧分离，游戏秒内 0..N 个可重放的订单/撤单/成交/新闻事件；每笔 Fill 具有持久化事件 ID、游戏时间戳、参与方、价格、数量，且具备确定性随机种子。
- NPC 不得有无限资金/库存，也不能透视未来玩家指令；做市商、趋势/价值/订单流、机构大单之间可因仓位和消息相互博弈。
- 连续维护形成中的 1m K（open/high/low/close/volume）和历史已完成 K；可进一步做 1s/5s/5m/15m。没有成交时显示零量并分离参考价，不伪造影线。
- 高频屏幕绘制只消费**已提交且可恢复**的事件；禁止将未经落库的幻想价格当真实成交。经济事件的处理速率、数据库提交批次、60fps/屏幕刷新频率分别控制，不应每秒写完整账本快照。

### B. 账务与存档结构整体重构

- 优先消除全 Fill × 全 Ledger 的二次遍历；同事务批量内部可做受约束的局部检查，持久化前仍有一次独立完整审计，异常必须失败关闭。
- 从完整 JSON 快照渐进迁移到 **追加事件表 + 按序检查点 + 独立 OHLCV 汇总 + 分页读历史**。同步确保旧 schema 1 数据只读核验、版本化迁移、断电回滚、幂等重放，不得删除任何有效历史。
- 100/500/1000 模拟分钟分别评估 p50/p95 写入耗时、数据库实际体积、启动恢复、UI jank、连续 60× 实际与目标速度；用实机数据选择 Dart、Kotlin 或 Rust 计算内核。需要性能收益和可靠的 Android CI 才切换语言。

### C. 交易 UI 和五市场玩法并行

- 行情页先改善价格涨跌、K 线十字线、盘口及真实逐笔、当前 K 状态；交易页整合限价/市价、按数量/金额快捷交易、VWAP 预估、费用/滑点和持仓成本线；清晰区分提示、标记价、参考价、真实成交价。
- 五市场使用 `InstrumentSpec/MarketRules/Calendar/PortfolioLedger` 模块配置：A 股 T+1/涨跌停/会话时段（差异按板块配置）；美股日内 T+0/盘前盘后及可能中断；期货多空/乘数/保证金/到期/强平（不同合约可能有涨跌限幅）；外汇基准报价币/24x5/双边换汇；加密现货 T+0/24x7，永续杠杆另建风控。不可把游戏简化规则伪称现实中所有交易所通用规则。
- 用户允许同一批横跨上述模块，只要拥有回归、可审计和可实际试玩的垂直切片；不发布空壳市场或假事件。MARL 离线训练与本地 RAG 助手是可选长期项目。
