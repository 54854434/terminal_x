## 0. 本轮 0.2.5 Android 截图和具体问题（最高优先级）

- 用户手机截图在 Android 前台真实显示 0.2.5、60×、SQLite r74、第67游戏分钟、K 图表步24–67；已能画蜡烛、MA 和成交量。不代表性能问题解决。
- **已反馈：** 仍有 K 线随分钟“一根一根加载/突然出现”的感受；很多蜡烛没有显著上/下影线；60× 稍微卡顿；冷启动偏慢。未来真实流动性、秒级事件驱动和首帧体验优先于新市场/UI 花哨动画。
- **机制解释：** 当前游戏每分钟集中撤单、报盘和 NPC 交易，最多一真实秒提交一个游戏分钟，展示新的实心 K 属于机制限制。真正 OHLC 由已入账 Fill、存档参考价格组合而成；高低端若与开收端重合可以没有影线，**禁止伪造影线/假成交量**。青色空心形成棒、秒级指示价格与虚线仍是非成交指示，不可偷偷合并历史。
- **根性能瓶颈：** `TxEngine.checkInvariants()` 在一个模拟分钟内被各次 place/cancel 反复执行，而且验证每笔 Fill 时再遍历全量 `_ledger`，历史累积后高复杂度；SQLite 每分钟保存含全部订单、逐笔及账务的 JSON 全量快照；手机冷启动 `readHistory(limit:64)` 为两个标的重建行情并再次解析多个增长的快照。先测再改，不能在无迁移安全验证时截断/清空旧快照。
- **其他操作问题：** 60× 是目标推进速率，提交慢则会暂停调度，实际速度可能低于 60×；图表布局、分时预览和历史加载状态需要明确标识。建议加入真实帧耗时、提交 p50/p95、数据库大小、启动恢复时长诊断，但不得记录或上传用户私人账户信息。

## 0. 核心定位：五大金融市场共享一个自洽的离线世界

**原始产品愿景：** 把 **中国 A 股、美股、期货、外汇、加密货币** 融合为一款 Android 离线、单人、长期可玩的专业交易与大资金操盘模拟游戏。玩家管理跨市场资金、仓位、风险和执行成本，与有真实约束的算法对手博弈；随机事件和不同市场制度制造不确定性，但**结果不由 UI 随机改写，也不为玩家作弊**。

此愿景是**目标架构，不是现有版本已经实现的功能**。当前可玩的底层仍以 `SIM-A01`、`SIM-A02` 两只合成证券和单一模拟市场为主。扩展市场前先保护现有账户、修复 60× 卡顿和逐笔真实性；不得为了五类市场的名义迅速添加大量空壳标的。

**游戏主循环：** 研究多市场报价、盘口、逐笔、事件和资金流 → 形成交易判断 → 选择订单、仓位、杠杆与风险预算 → 在有限流动性中成交或排队 → 记录成本、盈亏、手续费、保证金和回撤 → 观察对手反应与跨市场传导 → 调整策略并复盘。盈利和亏损必须能从可审计账务与成交还原。

**永久约束：** 完全离线运行；单机单人但存在 NPC 对手；不接入真实交易所/真实账户/真实资金；交易日志不可伪造；存档损坏时拒绝交易而非静默重置；签名/包名固定、向上覆盖安装；不删除用户历史旧 APK、私有 XML 或 SQLite 存档。

## 0.1 界面参考方向：借鉴 OKX 和 Gate，但形成 Terminal X 独立设计

**用户新增明确偏好（2026-10-12）：** 用户认为 **OKX、Gate** 的交易操作界面和信息内容比较舒适，后续 Terminal X 作为**交易终端型游戏**，应参考其手机端清晰、紧凑、可快速操作的交互风格。目标不是将交易所整页照搬、联网或接入真实交易，而是在保留 Terminal X 深蓝/近黑独立品牌、现有 X 图标及离线模式的前提下，让真实模拟市场的信息层级、操作效率和可读性达到更成熟的专业交易 App 水平。

**参考依据（官方公开说明，功能描述并非 Terminal X 当前能力）：**

- OKX [K 线图常见问题及设置](https://www.okx.com/zh-hans/help/candlestick-faqs-and-settings)：顶部价格/涨跌与市场信息、K 线周期与 MA 等指标、十字线 OHLCV、成交买卖点/挂单线、订单与持仓信息的可选择显示，作为行情分析布局参考。
- OKX [交易常用功能设置](https://www.okx.com/zh-hans/help/trading-settings-faq)：可调整 K 线与下单布局，订单簿聚合档位/价格精度，以及合约仓位快捷动作，作为按市场风险分层的参考。
- Gate [币币现货交易介绍](https://www.gate.com/zh/help/guide/deposit_withdrawa/17244?category=guide)：快速行情概览、24 小时统计、K 线与深度、委托区/最新成交、条件单和布局设置，作为紧凑信息分区参考。
- Gate [股票交易说明](https://www.gate.com/zh/help/tradfi/stock-spot/50969)：从 K 线页直接买卖、按数量下单、在委托/仓位/成交记录之间查看，作为移动端简化交易流程参考。

### 手机端信息架构：现有四页先精修，不急于增加导航层级

| 模块 | 借鉴的操作感与内容密度 | Terminal X 分阶段具体要求 |
|---|---|---|
| **行情（Market）** | 顶部标的切换、最新价与涨跌信息，K 线为主，下面切换盘口/逐笔/资讯 | 当前两合成标的保留；后续顶部市场分类（A 股／美股／期货／外汇／加密）+ 代码搜索、收藏与虚构标签；价格、涨跌、时间明确标注**实际成交价/参考价/标记价**；没有有效统计就显示“—”，不伪造 24h 成交额或市值 |
| **K 线（Chart）** | 1m、5m、15m、1h、1D 周期；MA 等指标；长按十字线 OHLCV；缩放拖拽、成交量、当前价线 | 初期优先修复 1m 的流畅度、冻结列宽/保留可视区域、绘制缓存；后续周期只由真实逐笔/已保存分钟数据聚合，不能简单复制或补假 K；实体/影线真实绘制；明确“正在形成/已收盘”；十字线轻量化；委托线/成本线与成交 B/S 需以玩家真实数据生成并允许关闭 |
| **交易（Order Ticket）** | 买/卖切换、限价/市价/条件单、数量或金额快捷档位、可用余额、盘口联动、委托状态 | 单手手机操作优先，常用字段始终可见，高阶参数折叠；点击盘口填入限价；下单前展示手续费（实现后）、预计多档均价/VWAP、最大滑点与**预估而非保证成交**；大单及杠杆触发风险确认；没有实现的止损/杠杆不得显示为可点击功能 |
| **资产（Portfolio）** | 总权益、可用资金、冻结资金、仓位成本、浮动/已实现盈亏、风险指标 | 保留现有账务口径；未来新增按市场/币种分组、组合敞口、保证金率/强平价（仅期货/杠杆）、持仓快捷平仓；标注估值基准和刷新时点，不把参考报价当成交或真实盈利 |
| **记录（Orders & History）** | 当前挂单/历史委托/逐笔成交分栏，价格、数量、状态一目了然 | 优先清晰区分**我的委托、我的成交、市场逐笔、模拟新闻**；支持撤单与历史筛选，页内仅加载可见数据，支持保留滚动位置；成交与账簿必须能追溯到真实引擎 Fill/Event |
| **模拟资讯/事件（Context）** | 在行情里提供简短新闻、品种信息与经济数据入口 | 先作为行情页的折叠模块或页内标签，不新增复杂首页；仅显示离线经济引擎**预先入账的虚构事件**及其游戏时间戳、影响范围，禁止借用未同步的真实市场快讯冒充游戏事件 |

**舒适操作的统一规范：** 深色低眩光主背景；清晰数字与金额字重；涨跌色可配置（中国红涨绿跌 vs 国际绿涨红跌），且**同时通过 +/−、↑/↓、文本标记**，不只靠颜色传达；统一价格/数量/百分比精度及单元（股、张、手、币、基准/报价货币）；小屏幕单列优先，折叠次级信息，触控目标足够大，避免看得见却点不到。切换品种/市场/页面时尽可能保留图表缩放、周期、滚动和下单草稿；避免误操作的快捷开仓、平仓和撤单须有状态与风险反馈。

**性能与真实性优先级高于复刻外观：** K 线隔离绘制与 MA 缓存、历史分页、增量列表和最小状态刷新；盘口/价格/资产更新有明确数据源。高倍速下不能因为增加行情卡片、闪烁涨跌或花哨动画重新引入主线程卡顿；不能把“秒级指示价”的动画误导成秒级真实成交。首批 UI 优化先解决真实用户反馈的卡顿、K 棒跳出、布局稳定，再逐步追加十字线、委托线、市场总览和条件下单。

**品牌/IP 边界：** 允许学习 OKX 和 Gate 的常见金融界面信息架构、交互模式和专业信息密度，**不复制其 logo、独家插画、图标资源、截图、品牌命名或专有文案**。Terminal X 保持原有深蓝 + 青绿设计语言和 GitHub 已提交的应用图标；后续无须为此设计方向额外打包任何 PNG/JPG。

**实现/验收状态：** 以上仅为**长期设计决策**，**没有因本次文档更新而改写任何 Flutter UI 代码**，不包含在 V0.2.5 已完成或已验证功能列表中。需要后续按单 ZIP 批次开发，CI/手机验收后再标记已实现。

## 1. 五大市场的游戏规则设计（拟议，而非真实交易所规则声明）

| 市场 | 推荐的差异化玩法 | 拟议的市场制度及风险 | 首批开发边界 |
|---|---|---|---|
| **A 股** | 资金占用、隔日交易、涨跌停排队、成交受限 | 以普通股票 **T+1 卖出、示例 ±10% 日涨跌幅** 为基础预设；细分 ST/不同板块/上市初期另配；交易时段、集合竞价、交易单位、费用需由交易日历与合约配置控制 | 先单独测试 T+1、涨跌停、冻结和跨日释放，不直接套用现有全天沙盘钟 |
| **美股** | 日内交易、隔夜跳空、财报、流动性差异 | 游戏股票可采用日内 **T+0 买卖**、无统一普通日涨跌幅上限；熔断、波动中断、盘前盘后、结算资金等需分开建模；不可写成现实中“永不熔断” | 先实现常规交易时段与事件跳空，现金结算／融资规则独立配置 |
| **期货** | 多空、保证金、逐日盯市、移仓、强平 | 以 **T+0**、合约乘数、初始/维持保证金、到期日、保证金追缴和强制减仓为核心；**并非所有真实期货都无涨跌限制**，波幅/熔断属于合约规则 | 先用单个虚构合约验证双向头寸、冻结保证金、权益变化和守恒 |
| **外汇** | 双向报价、点差、汇率交叉影响、隔夜持仓成本 | 游戏采用近似 **周内 24 小时、周末休市（24/5）** 的场景；汇率有基准/报价币种、点值和换汇损益；杠杆交易须作为独立衍生品模式，不把现货换汇等同保证金外汇 | 优先完成多币种余额、成交汇率、兑换手续费及汇率一致性 |
| **加密货币** | **24/7** 连续市场、流动性突变、周末风险、资金费率 | 先实现 **T+0 现货**；可选永续合约才增加杠杆、资金费率、标记价/强平价和保险机制；现货不天然存在爆仓 | 先验证连续市场时钟、盘口冲击，杠杆/资金费率后置 |

**规则原则：** 表中 T+1、±10%、24/5、T+0 等是设计起点。真实交易规则因交易所、板块、账户类型、合约和时间变化而异；未来设置“仿真模式/简化模式”时必须明确标记，不能把统一简化规则宣称为对全部真实证券适用。当前 `24 小时游戏钟` 只是沙盘时间，不自动等于任何交易所日历。

**差异要能玩出来：** A 股有卖出受限和涨跌停无法退出，美股有盘前/盘后与跳空，期货有保证金和到期，外汇有货币转换及隔夜成本，加密现货有不间断交易；同一个下单引擎由不同 `MarketRules` 控制，而不是五套完全复制的游戏或五张贴图。

## 2. 统一虚拟经济系统：价格必须能解释“为什么变”

### 2.1 共同经济状态与跨市场传导

- **宏观状态变量：** 增长/衰退、利率与通胀预期、流动性、美元强弱、风险偏好、行业景气、监管及突发供需。以**存档中的确定性随机种子、事件序号和状态**驱动，不依赖联网行情或云端 AI。
- **基本价值与市场价格分离：** 每个 NPC 可有主观估值或目标仓位；实际可成交价必须由**有资金/库存支持的挂单与撮合**产生。经济事件修改各参与者的信息、风险预算、估值或需求，而非直接将图表中的历史价格改写为随机曲线。
- **跨市场相关性与冲击：** 例如流动性骤降可使美股风险资产卖盘增加、外汇避险币种需求变化、期货保证金压力触发去杠杆、加密盘口变薄；它们通过同一事件及代理人的决策发生，不强制价格每天同涨同跌。
- **事件新闻：** 引入政策、财报、经济数据、利率、供应中断、交易所暂停、加密流动性事故等**明确虚构的、带时间戳的模拟新闻**。事件先进入可回放日志，再改变模拟者行为；支持事件前后成交复盘，不允许事后挑选走势来“解释”玩家盈亏。
- **市场时钟：** 各市场有独立时区、交易日历、休市、盘前盘后、结算时点和事件响应；唯一游戏时间轴协调它们，不能让 A 股在休市时产生正常连续竞价逐笔。

### 2.2 订单、成交、K 线和账户的一致性

- **撮合：** 价格优先、同价 FIFO；支持市价/限价，逐步增加止损/止盈、条件单及部分成交/撤单。资金、股票库存、保证金和卖空借券规则必须在撮合前预检；禁止自成交和重复订单导致重复记账。
- **真实行情：** 盘口因挂单/吃单/撤单变化；只有真实 `Fill` 计入逐笔、成交量、VWAP、成交价 OHLC 和滑点。没有成交时允许零成交量；若显示参考/标记价必须标识为**非成交价**。K 线无影线可能是高低价恰等于开收端点，**不能为好看制造影线**。
- **大资金风险：** 盘口深度、冲击成本、流动性枯竭、撤单、执行速度、交易对手资金耗尽、价格跳空必须真实影响大单执行；资金更多意味着风险和策略更多，而非自动能以中间价无限成交。
- **账户与负债：** 现货现金和库存守恒；衍生品单列保证金、逐日结算、未实现/已实现盈亏、费用、融资/借券/隔夜成本、强平和亏损穿仓处置。兑换需有币种与对价双边记录，不能把外汇价格变化当凭空现金。
- **行情周期：** 最终计划支持 1s/5s/1m/5m/15m 等由真实成交汇总的 OHLCV 和正在形成的 K 线；成交事件量不等于刷新帧率。任何显示级平滑/插值必须与真实成交视觉上区分。

### 2.3 可扩展的统一架构（目标模块；当前并未全部存在）

1. **InstrumentSpec / MarketRules：** 品种类型、报价币、最小价格跳动、交易单位、可卖时间、开收盘、涨跌幅/熔断、费率、杠杆与合约乘数。
2. **MarketCalendar / SimulationEventClock：** 全局事件序号、市场会话、开休市与结算；经济逻辑与前台绘图节拍分离。
3. **OrderBook / MatchingEngine：** 市价、限价、撤单、部分成交、价格/FIFO、有限资源；统一适配不同制度。
4. **PortfolioLedger / MarginRisk：** 现金、冻结、库存、借贷、费用、多币种换算、保证金、盯市、强平、风险集中度和回撤；跨市场资产净值口径清晰。
5. **WorldState / NewsEvents / NpcAgents：** 事件、信息、对手策略、反应延迟、独立资产、可重放确定性种子。
6. **Persistence / Audit / Replay：** SQLite 追加式订单事件、逐笔与账务流水 + 周期检查点；事件 ID 严格单调、幂等、同一事务原子提交；升级迁移只读核对并失败即停止，绝不清空老账户。

**不允许直接一次性重写现有稳定撮合内核。** 采用适配层及版本化迁移，先实现测试和数据一致性，再引入新市场。旧 SQLite schema `1` 和 V0.2.4 玩家账户为兼容基准。

## 3. NPC 与 AI：对手先可信，助手后选择

### 3.1 离线、有限预算的异质 NPC

当前原型已有趋势、逆势/价值、订单流、流动性提供者四类 NPC，加上做市商。后续细化为库存敏感做市商、长期价值投资者、日内动量交易员、套利/对冲参与者、被动指数与机构执行者、冲击性流动性需求者。每类 NPC 必须有**真实且有限的资金、库存、保证金和风险限额**，并带可解释目标、反应延迟、挂单寿命、撤单概率与市场信息范围。

NPC 可以识别价差、流动性、新闻、库存与风险，也可以因为错误判断而亏损、触及保证金或退出市场。**不能偷偷读取玩家未来指令、无限印钱印货、确保玩家失败/盈利或私改账本。** 若设计操纵与异常交易作为教育性风险情景，应通过可审计的订单行为呈现，同时设置市场监管/风险机制，而不是直接“导演”行情。

**MARL（多智能体强化学习）是长期研发选项，不是 V0.2.x 前置条件。** 先采用可解释、可测试的规则/效用策略；若以后实验训练策略，可离线训练、小模型部署、固定种子复现实验，并比较其对真实性、帧时间、内存和电量的收益，且保留规则策略作为降级路径。单机离线并不要求在 Android 手机上实时训练复杂模型。

### 3.2 可选 AI 助手（不破坏离线约束）

RAG 投资组合/教学助手是**可选后期模块**：优先提供纯本地的规则说明、当前模拟账户分析、风险敞口、费用/滑点解释、复盘摘要和策略教学；需要知识检索时只检索打包/本地生成的文档和本地数据，不调用云模型、不联网、不访问私人真实金融账户。若模型推理性能不足，可用确定性规则及离线检索先替代。助手提供信息与解释，不代玩家偷偷执行交易，不承诺收益。

## 5. 开发优先级与里程碑：先性能，再真实市场，再五类市场

### P0｜V0.2.5 本批：针对用户反馈的局部修正（候选，待 CI）

- 固定图表指示 K 的预留空间，降低分钟切换时历史柱横向跳动；已提交 OHLC 与指示价明确区分；无影线/无成交必须真实显示，不美化造价造量。
- 缓存 MA5/10/20，减少秒级绘图时重复计算；图表滑动与缩放保持原有交互。
- `nextTick` 的市场克隆/模拟 NPC 撮合移向 Dart 后台 isolate，并发操作仍受存档修订约束；SQLite 成功提交之后才能更新可见账户。
- 库存敏感做市报价、带资金约束的主动 NPC 行为；只读盘口多档扫单/VWAP/滑点估算模块（**暂未接 UI 下单票据**）。
- 100、500、1,000 游戏分钟 SQLite 压测脚本与资金/账本/市场/UI 回归；14 个 `tx_*_test.dart` 测试文件由既有单 ZIP 工作流统一执行。
- **不宣称：** 真正秒级成交、所有 K 都带影线、60× 绝不卡顿、SQLite 全量快照已消除。这些仍是下一阶段。

### P1｜性能与存档体系（五市场的前置阻断项）

- 量化延迟：100/500/1000 游戏分钟时提交耗时 p50/p95/最慢值、APK 启动恢复、SQLite 大小/增长曲线、Flutter 主线程帧时间、缩放/切页响应、内存峰值。**先测指标再定验收阈值**。
- 解决 `TxEngine.checkInvariants()` 对每笔成交反复扫描全部流水的高复杂度路径；改为有索引/增量汇总但保留独立完整审计核验，不以删除账本换取速度。
- 将每分钟**完整会话 JSON 与全部历史快照**逐步迁移到追加事件流 + 周期检查点 + 可分页历史，事件与账户状态原子持久化、校验和、严格序列与幂等恢复。
- 启动、后台、突然关闭、数据库写入失败、旧版本升级均必须保持同一现金/持仓/未结委托/成交/时间；损坏只能只读或停止，不得创建空白账户覆盖原档。必要时保留只读旧格式与安全迁移检查点。

### P2｜真正的时间内订单事件与行情

- 从“每游戏分钟集中交易”改为**每游戏秒零到多次订单/撤单/撮合事件**；逻辑时钟、绘图刷新、SQLite 事务/批处理节奏分开。
- 每笔真实成交附带游戏时间戳、双方身份、价格、数量；按真实逐笔生成 1s/5s/1m/5m/15m OHLCV，明确正在形成的柱和零量柱；报价波动只改变盘口或非成交标记价。
- 深化 NPC 风险预算、反应延迟、库存管理、突发流动性枯竭；用户可见订单排队、部分成交、滑点与价格冲击，不通过改写随机 K 线模拟热闹。

### P3｜专业账户、下单、风控与舒适的交易界面

- 费用和资金冻结、可卖数量、仓位成本、风险限额、组合净值、已实现/浮动收益、峰值回撤、滑点估算、订单生命周期与逐笔复盘。
- 参照 §0.1 的 OKX/Gate 移动端信息架构逐步打磨行情、图表、买卖、持仓、记录；先适配小屏/数据来源与高倍速流畅度，再扩展十字线、委托/成本线、盘口联动。限价/市价票据改善，新增止损等条件单必须定义触发源（真实成交价、盘口或标记价）、触发时仍面对真实流动性；止损不是保证成交价。
- 融资/杠杆等高风险功能必须先有可靠负债与保证金账务、审计和强平测试，再暴露给玩家。

### P4｜五市场分阶段开放（长期目标）

1. 先将**现有两只合成证券**配置成不同流动性生态，完成 `MarketRules`、日历、币种与费用抽象；不破坏旧存档结构。
2. 建立 **A 股式沙盘与美股式沙盘** 的差异化规则，验证 T+1 卖出限制、涨跌停、开休市、日内流动性与跳空；测试旧账户在同机升级后的隔离与权益。
3. 增加 **加密现货** 作为 24/7 对照市场；测试三类时钟同时推进、跨市场风控、休市期间头寸及事件传导。
4. 引入 **外汇多币种兑换**，确保汇率交叉、报价/基准币、现金换汇与风险敞口守恒；随后探索杠杆外汇衍生品。
5. 最后引入 **期货和其他杠杆/永续产品**，在已有可靠保证金、盯市、到期、费用与强平机制后开放。

**顺序可依据原型测试调整。** 目标是最终五类市场都具有明显不同的实际交易后果，并且共享可解释经济事件，不是一次发 5 个只有名称不同的行情页面。

### P5｜长期 AI / 内容深化

- 离线新闻与市场环境挑战（流动性危机、宏观加息、财报冲击、机构大单、不同市场同日风险）；保持无强制剧情的自由沙盘。
- 可离线训练后部署的 MARL NPC 策略实验，先和透明规则 NPC 比较可玩性、守恒与性能；无需手机实时训练。
- 可选本地知识库/RAG 风格助手：教学、风险解释与复盘，不联网、不操纵价格、不自动下单。
